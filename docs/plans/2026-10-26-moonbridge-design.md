# MoonBridge 设计说明

日期：2026-10-26

## 目标

MoonBridge 面向需要把 MoonBit 模块集成到普通 C/C++ 工程的开发者。它从 MoonBit 的 `#export_name` 声明生成 C 头文件，并提供 Linux 静态/共享库构建入口。首版只接受工具链文档明确给出 C ABI 映射的简单标量类型；遇到 GC 管理对象、字符串、数组、可变长布局或不支持的签名时，报出带源位置的错误，不生成看似可用但 ABI 不安全的声明。

## 方案比较

1. **扫描 MoonBit 源码并复用工具链构建**：从 `pub fn` 与紧邻的 `#export_name` 中读取签名，检查类型映射，再生成 `.h`。构建端调用 MoonBit 编译器，围绕它生成的 C 代码和运行时产物完成静态/共享库链接。优点是头文件来自真实 API；缺点是要适配 MoonBit 生成物和 linker。推荐。
2. **只读手写 JSON 清单**：根据用户重复维护的签名生成头文件。实现简单，但清单会和 MoonBit 函数漂移，也容易掩盖不匹配的 ABI，不作为主流程。
3. **扩展平台专用桥接项目**：可借鉴 MoonOHOS 的清单和桥接生成方式，但会把项目限制在单一宿主平台，并与现有生态项目重叠；不选。

## 组件与数据流

`moonbridge` CLI 接收包目录、输出目录和库名。MoonBit 扫描器枚举包内生产 `.mbt` 文件，识别导出属性和函数签名；ABI 模块把允许的 MoonBit 类型映射为 C 声明，并拒绝 unsupported/managed 类型；renderer 以稳定排序生成带 include guard、`stdint.h` 和 C++ `extern "C"` 的头文件；构建器将编译器输出与平台 C linker 串接，生成 `.a` 和 `.so`。生成文件先写临时路径，完整成功后再替换目标，避免留下半成品。

首版限定 Linux x86-64 和简单标量参数/返回值；不自动导出 `String`、`Bytes`、数组、闭包、泛型、可选参数、错误类型或需要调用方管理 MoonBit 对象生命周期的接口。Linux `.so` 由包生成的 C 源及配套 runtime C 源重编 PIC 后链接；已拒绝带 `TEXTREL` 的输出。当前示例还验证了一个导出函数在内部申请 MoonBit 数组后可经 `.a`/`.so` 被 C/C++ 调用，不需要调用方传递或释放 MoonBit 对象。

## 错误处理与验收

扫描阶段检测无效/重复 C 符号名、缺失或不支持的签名；构建阶段检查 MoonBit 命令和 C compiler 的退出码，并将 `.h`/`.a`/`.so` 先写到同目录临时路径，完整成功后再替换目标。验收包括：单位测试覆盖词法/签名/类型映射/错误；端到端示例构建库；独立 C 与 C++ 程序包含生成头文件并调用导出函数；`nm` 验证导出符号、`readelf` 拒绝文本重定位；同一输入得到字节一致的头文件。所有 MoonBit 代码运行格式、静态检查和测试。

## 风险边界

官方文档确认 `#export_name` 和基础 C ABI 映射存在，但不承诺 native 后端直接产出共享库。已在 `moon 0.1.20261023` / `moonc v0.10.17` 下验证 Linux `.a`、PIC 重编译与 `.so`。该 `.so` 流程依赖工具链附带 runtime C 源和 GCC 兼容编译器；若工具链版本改变运行时对象/源码布局，脚本必须明确失败并保留已有输出，不能回退到有文本重定位的库。
